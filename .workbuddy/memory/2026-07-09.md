## 设计要点（用户原话「只要过程，数据每次单独存储」）

## 实际跑通（验证踩到的坑 — 下次直接用）
1. **`scrapling.parser.Adaptor` 的第一个参数是 `content`，不是 `text`！**
   `Adaptor(text=body)` 拿不到内容（content=None），会抛 "Selector class needs HTML content"。
   ✅ 正确：`Adaptor(content=body)`。
2. **没有 `css_first` 方法。** `css("h1")` 返回 `Selectors`（pyquery 风格），用 `.first` 取第一个。
   错误：`page.css_first("h1")` → AttributeError。  
   ✅ 正确：`page.css("h1").first`（空集时 `.first` 返回 None）。
3. **`page.text` 是 `TextHandler` 包装类，不是 str。** 不要直接把 `page.text` 当字符串传给下游。
   ✅ 直接用 `page.body`（bytes），下游按 charset 解码。
4. **JSON 端点不能用 `Adaptor`**。`wanzhan/api52/xiaoshuo/gutendex/openlibrary/pansou_252`
   这些是 JSON 源，要走 `json.loads()` 路径，**不要** 给 `selector()`。
   `selector()` 内置 HTML 检测会抛 `ValueError` 提示。
5. **Playwright Sync API 不能跑在 asyncio loop 里**。
   错误：`Page.goto: Timeout 15ms exceeded` / `It looks like you are using Playwright Sync API inside the asyncio loop`。
   ✅ 把 http.get 放进 `asyncio.to_thread(...)` 或 `loop.run_in_executor(None, functools.partial(call, **kwargs))`。
   注意 `run_in_executor` 不接受 kwargs，必须 `functools.partial` 包装。
6. **`DynamicFetcher.fetch` 的 `timeout` 是毫秒，不是秒**。
   错误：传 `timeout=15` 被当成 15ms 立即超时。
   ✅ `http.py` 内部自动 `timeout * 1000` 转换。
7. **Scrapling 内部 cssselect 要求 attribute value 带引号**。
   错误：`a[href*=/txt-xx/softdownfree.asp]` → `SelectorSyntaxError: Expected string or ident, got <DELIM '/' at 8>`。
   ✅ `a[href*="softdownfree.asp"]`（去掉前导 `/`，quote 包围值）。
8. **`HaiSouSource` 4 套 selector 模式（Pattern A-D）必须首套命中即停**。
   原因：不同 Pattern 可能匹配同一元素，叠加 yield 会重复。
   ✅ dedup 用 `(title, url)` 在 parse 出口处去重即可。
9. **`Selector` 对象的 `id()` 不能用于 dedup**（每次 `page.css()` 都返回新对象）。
   ✅ 用业务字段（title+url）做 dedup key。

## 根因（已确认）
**`WebView.evaluateJavascript` 双重 JSON 编码。**
- 原 `JsExtractors` 6 个脚本都 `return JSON.stringify(items)`（返回 JS 字符串）
- Android WebView 会对返回值再做一次 JSON 编码 → Kotlin 端收到 `"[...]"`（带转义引号的**字符串**）
- `JSONArray(raw)` 首字符是 `"` → 抛 `JSONException` → 触发 `SearchOutcome.Failure.parse("解析失败: ...")`
- 判据：用户看到"解析失败"而非"WebView 抓取失败或超时" → 说明 `raw` 非 null，正是双重编码特征

## 修复
`JsExtractors.kt`：6 个脚本全部改为**直接返回数组/对象**（去掉 `JSON.stringify`）。
WebView 把数组/对象编码成 `[...]`/`{...}`，Kotlin 端 `JSONArray`/`JSONObject` 正常解析。
同步把顶部契约注释从"返回 JSON.stringify 字符串"改成"直接返回值"（原注释本身就是 bug 来源）。
